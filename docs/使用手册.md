# 授权模块使用手册

本文给开发和运维使用。它说明这套授权服务做什么、为什么这样设计、代码怎样串起来、后台怎么操作、桌面程序怎样接入，以及常见故障怎么看。

当前交付是厂商云上的授权服务，加上给桌面程序用的客户端库、WinForm 授权窗体和命令行示例。没有客户门户，没有客户机房里的许可服务器，没有客户提交的离线申请文件，没有加密锁远程写锁，也没有访问频率限制。单机许可可以由管理员预签一份授权文件，客户拷到不上网的电脑上导入。

## 1. 总述

四个项目：

| 项目 | 目标框架 | 作用 |
| --- | --- | --- |
| `src/Licensing.Server` | .NET 10 | 授权 API 和管理后台，在同一个 ASP.NET Core 进程里 |
| `src/Licensing.Client` | .NET Standard 2.0 | 桌面程序引用的库。不读硬件，不调用加密锁 SDK |
| `src/Licensing.WinForms` | .NET Framework 4.8 | 单机许可的授权窗体，也可单独运行来走通授权过程 |
| `src/Licensing.Sample` | .NET 10 | 命令行示例，演示激活、心跳、离线检查、注销和换机 |

解决方案文件是 `Licensing.slnx`。开发时机上需要 .NET 10 SDK。

服务端保存客户、产品目录、许可和激活记录。桌面程序拿产品标识、许可码和本机机器码访问服务器。服务器验过之后签发一份 RSA 签名的短期授权。程序断网时用这份授权继续运行，直到其中的到期时间。

一张许可只属于一种绑定：

| 种类 | 绑定方式 |
| --- | --- |
| 单机 | 第一次成功激活或管理员预签文件时写下的那台机器 |
| 机器池 | 最多 N 台已登记机器。界面上的“使用人备注”只是标签，不是登录账号 |
| 浮动 | 同时在线的机器数。一台机器上的多个进程算一个席位 |
| 加密锁 | 锁号。机器码只作到访记录，不作为绑定条件 |
| 导入老码 | 不绑机器。空白、横线和大小写在比对时忽略 |

商业形态是永久许可、带到期日的订阅、版本加功能代码、浮动席位，以及由管理员签发的短期订阅（试用）。没有借出。永久许可不按软件版本号设门。程序版本号可选，心跳里带上之后记在激活记录上。

### 谁看哪些数据

后台只有内部账号。超级管理员看见全部客户，并负责产品目录、账号和签名密钥。普通账号只看见分配给自己的客户，可以在这些客户上签发、修改、暂停、恢复、吊销、导入、强制释放和后台换机。普通账号新建的客户会自动分给自己。把某人改成超级管理员之后，对方要退出并重新登录，菜单才会变成 7 项。

### 运行数据放在哪里

服务端内容目录下的 `storage/`：

| 文件 | 内容 |
| --- | --- |
| `storage/licensing.db` | SQLite 数据库 |
| `storage/keys/*.pfx` | RSA 私钥。不要进备份以外的拷贝，不要提交到仓库 |
| `storage/signing-password.txt` | 未在配置里写死 PFX 口令时，首次启动生成的口令 |
| `storage/public-keys.json` | 公钥。桌面程序编译时带上它，或由安装包分发 |

这个目录名故意不用 `data`。在 Windows 上 `data` 和源码目录 `Data` 是同一个文件夹。

客户端缓存按当前登录的 Windows 用户分开存放。不传缓存根目录时，根位置是 `Environment.SpecialFolder.LocalApplicationData`。这个目录属于该用户，普通权限就能写，也不在「程序文件」里。授权绑的是这台电脑，所以用 Local，不放进会跟着漫游配置文件走到别的电脑的 Roaming。

库再固定拼上 `Licensing`、产品标识和文件名：

- Windows：`%LOCALAPPDATA%\Licensing\{产品标识}\grant.json` 和 `state.json`
- Linux：`~/.local/share/Licensing/{产品标识}/` 下同名文件

`grant.json` 是签名授权。`state.json` 记录时钟高水位、导入时记住的许可码，以及已经确认的拒绝（暂停、吊销、到期）。一个产品一份。产品标识里不能做文件名的字符会换成下划线；现行标识只允许字母、数字、点、下划线和横线，因此目录名与标识相同。

根目录可以改，后面这两级和两个文件名不能改。`LicenseClient` 的第 5 个参数 `storeRoot` 替换上面的 LocalApplicationData。例如传入 `D:\MyApp\license` 时，文件在 `D:\MyApp\license\Licensing\{产品标识}\grant.json`。导入、离线检查和心跳必须用同一个根目录，否则会读到另一套文件。

### 信任边界

库信任宿主程序送来的机器码和加密锁快照。被改过的宿主可以伪造这两项。真正的锁认证要等以后的厂商锁 SDK，不在本库里。

服务器上的吊销、暂停和到期，要等这台机器下一次成功连上服务器才会落到本地。已经拷走的预签文件也一样，在它自己的到期日之前仍然有效。删掉用户目录里的 `state.json`，可以清掉已经写入的拒绝记录。从未连过服务器的加密锁，只要宿主能给出锁快照，离线检查会当作有效。

## 2. 设计思路

三种现成做法叠在一起，而不是互相替换。

序列号对应 JetBrains、Windows 那种“先发码，客户第一次联网时绑定机器”。加密锁对应 Sentinel、CodeMeter、深思、飞天那种“锁在客户机器上，服务器只记锁号、客户、功能和吊销”。定期访问服务器对应 Adobe、Autodesk 那种“在线租约加离线宽限”。服务器是唯一的签发方。客户现场不部署许可服务器。

### 为什么签发单机许可时不填机器码

签发时通常还不知道客户电脑的机器码。管理员发出一张尚未使用的许可码。客户在程序里输入后，程序读出本机机器码并调用激活。服务器把这次的机器码写到这张许可上。另一台机器再激活，得到“许可绑定在另一台机器上”。

客户电脑当时上不了网时，改用管理员预签。客户先把机器码抄给管理员。管理员在这张单机许可上填写机器码和文件到期日，服务器立刻绑定这台机器并签出一份授权文件。客户把文件拷进电脑，程序验签后写入 `grant.json`。文件在生成时就占住这台机器；文件丢了、客户还没导入，也要强制释放，席位才会空出来。机器码抄错时，服务器绑的是那串错误的码，真电脑会报机器不一致，强制释放后按正确机器码重签。

预签只做单机。机器池、浮动、老码和加密锁这一版不预签。浮动席位靠心跳维持，预签会把席位提前锁死，和借出是同一类问题。加密锁本身已经可以离线使用。

文件到期日每次都要填，不能签永不到期的文件。页面默认填今天起 365 天。订阅若更早结束，默认改成订阅结束日。订阅许可旁边有「直到订阅结束日」，把 365 天改成订阅结束日当天，时间是该日 23:59:59 UTC，不会晚于订阅结束。管理员手填得更晚时，签出来的文件仍收到订阅结束日。永久许可没有这个按钮。

这份到期日管的是文件，不改许可本身的订阅结束日。客户一直不上网，就没有心跳可以续期，文件到期前要再签一份。同一台机器的续签不计每年的自助换机次数。给另一台机器预签等于后台换机，也不占客户的自助次数。旧电脑上已经拷走的文件撤不回来，两台会各自用到自己文件的到期日。

以后这台机器心跳成功，新授权的到期日取「现在加宽限」和「手头这份授权的原到期日」里更晚的那个，并且不超过订阅结束。偶尔连上一次网，不会把一年收成 7 天。暂停、吊销或订阅已经结束时，心跳直接拒绝。本地若已记下拒绝，再次导入旧文件也会被拒绝，直到下一次成功的在线激活清掉记录。时钟回拨仍然只警告。

机器码由宿主程序提供，是不透明字符串，要求逐字相等。示例在 Windows 上读 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`，在 Linux 上读 `/etc/machine-id`。允许虚拟机。不用 CPU 标识，因为 ProcessorId 会撞车。

换机按许可、按 UTC 日历年计数。`0` 表示客户不能自己换，只能后台换。从机器 A 换到机器 B 计 1 次。同一台机器注销后再激活不计。管理员后台换机不计。机器池里还有空位、第一次占用空位时不计。机器池已经满员时，客户自己的换机不会自动挤掉一台；管理员后台换机才会挤掉最久没有心跳的那台。

### 离线只有一个窗口

单机、机器池和老码没有第二段宽限期。每次在线成功，服务器重新签名一份授权，到期时间是下面两者中较早的那个：

- 服务器当前时间加上宽限
- 订阅结束时间。永久许可只用宽限

签发页默认宽限 7 天、心跳 12 小时、浮动席位 12 小时无心跳后释放。签名本身就是这一个窗口的容器。客户端校验的是服务器写下的那一段规范字节，不会自己再序列化一遍。

浮动许可在宽限期内可能超卖：进程退出后席位仍要等到释放时间，而本机授权在 `exp` 之前仍然可用。单机和机器池不会因为错过心跳而放开绑定，只能由客户注销或管理员强制释放。

### 加密锁和老码

加密锁的功能在离线时始终来自宿主给出的快照。服务器在线时只决定放行或拒绝。快照和服务器记录不一致时记下来，不据此改客户机能用的功能。到期、暂停、吊销只在一次成功的在线调用之后生效。一直不上线的锁继续可用。一旦在线得到过期、暂停或吊销，客户端删掉授权并写下拒绝，之后的离线检查也停止。

老码按导入时的字符串匹配，不绑机器，不限制同时使用的机器数。服务器记录每次到访。每台机器有自己的 7 天签名缓存。撤销和到期同样只在成功在线之后生效。

### 时钟

本机时间比上次见到的时间早 5 分钟以上时，只记一笔警告，并在下一次心跳里上报。不拒绝，也不把高水位往回拨。

### 密钥

新许可码 25 位，5 位一组，字母表是 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`。签名是 RSA-2048、SHA-256、PKCS#1 v1.5。私钥在数据库外的 PFX 里。授权里带密钥编号 `kid`。客户端内置或加载多把公钥（模数和指数的 Base64，因为 .NET Standard 2.0 不能导入 SPKI）。公钥在编译或安装时固定，运行时不从服务器下载。轮换后旧公钥仍留在 `public-keys.json`，已发出的授权还能验。

调用 API 不使用客户端共享密钥。身份是产品标识、许可码和机器码。加密锁可以带许可码再核对锁号，也可以只带锁号。同一个锁号对应多张许可时返回请求无效。

### 数据

现在用 EF Core 和 SQLite。业务代码使用可移植的 CLR 类型，不写 SQLite 方言。以后换 PostgreSQL 需要新的数据库提供程序、一套新的迁移，再把数据拷过去，不是只改连接字符串。SQLite 不能按 `DateTimeOffset` 做 `ORDER BY`，列表排序和三年审计清理都在内存里完成。

审计保留 3 年，包括登录、客户变更、签发和修改、暂停、恢复、吊销、导入、强制释放、后台换机、预签离线授权、账号和密钥操作。心跳不进审计。后台每 2 分钟释放超时的浮动席位，并删掉超过 3 年的审计。

## 3. 实现过程

### 启动

`Program.cs` 把 SQLite 路径收成内容目录下的绝对路径，注册 Identity、Blazor Server、签名服务和定时维护。密码至少 8 位，要有大写、小写和数字，不要求符号。连续失败 5 次锁定 15 分钟。登录 cookie 保留 14 天。超级管理员策略看声明 `super=1`。这个声明在每次签发登录凭证时按账号上的超级管理员标记生成，凭证稍后自动续期时也会带上，不会过一段时间自己消失。

首次启动执行 EF 迁移 `20261105141123_Initial`。库里还没有签名密钥时生成一把，写入 `storage/keys/k年月日时分秒.pfx`，并把公钥导出到 `storage/public-keys.json`。库里还没有账号，且配置了 `Bootstrap:Email` 和 `Bootstrap:Password` 时，创建超级管理员。这两项为空则只记一条警告，不创建账号。

登录和退出是普通 HTTP 表单，不是 Blazor 回路里的调用，否则 cookie 写不进去。这两个地址关闭了防伪令牌。界面默认 `zh-CN`。右上角链接访问 `GET /culture?culture=en&redirectUri=...`，把语言写进 cookie。API 看请求头 `Accept-Language` 是否以 `en` 开头。

### 一次激活

1. 客户端 `POST /api/v1/activate`，正文是产品标识、许可码、机器码，以及可选的程序版本、时钟回拨标记、加密锁快照。
2. `ClientLicenseService` 按规范化后的许可码和产品标识找许可。没有码时按锁号找。
3. 暂停、吊销、订阅到期直接拒绝。注销则释放这台机器的激活并返回 `Released`，不签发新授权。
4. 单机和机器池走绑定：已占用则拒绝或换机；有空位则记下这台机器。浮动先释放超时席位再数人数。加密锁和老码只记到访。
5. `SigningService` 对规范 JSON 签名。在线激活的 `exp` 取宽限结束、客户端手头仍验得过的授权到期日、订阅结束日三者中的结果：先取宽限和手头到期日里更晚的，再不超过订阅结束。加密锁的授权里也有 `exp`，客户端离线时忽略它。
6. 客户端先验签，再把服务器返回的规范字符串原样存进 `grant.json`。验签失败则不保存。若这次签出的许可标识和本机保存的不是同一张，而且请求用的就是当初导入的那张许可码，客户端不替换本地文件。

四个地址和 HTTP 状态：

| 地址 | 成功时的状态 |
| --- | --- |
| `POST /api/v1/activate` | 200 `Active` |
| `POST /api/v1/heartbeat` | 200 `Active` |
| `POST /api/v1/deactivate` | 200 `Released` |
| `POST /api/v1/rehost` | 200 `Active` |

其他状态：404 是 `NotFound`；403 是 `Expired`、`Revoked`、`Suspended`；409 是 `SeatLimit`、`MachineInUse`、`RehostLimit`、`DongleMismatch`；其余业务拒绝是 400；未处理异常是 500 `ServerError`。

规范授权的字段顺序固定，UTF-8，中间没有多余空白：`v`、`kid`、`lic`、`prd`、`kind`、`ed`、`feat`、`mid`、`did`、`iat`、`exp`、`subEnd`、`perpetual`、`offlinePolicy`、`hbSeconds`。功能代码按字符序排列。时间格式是 `yyyy-MM-ddTHH:mm:ssZ`。`offlinePolicy` 为 `Grace` 或 `Dongle`。

### 客户端库怎么处理结果

网络失败返回 `Unreachable`，不删本地缓存。`Active` 保存授权并清掉拒绝记录。`Released` 删掉授权，不写拒绝。`Revoked`、`Suspended`、`Expired` 删掉授权并写入拒绝，之后的离线检查直接返回该状态。

离线检查 `CheckOffline` 不访问网络。单机和机器池核对机器码和 `exp`。老码忽略机器码。加密锁忽略 `exp`，用本次快照里的版本和功能。没有授权、没有拒绝记录、但本次带了锁快照时，返回有效，消息表示尚未经过服务器确认。

库不自己定时心跳。宿主按授权里的 `hbSeconds` 决定何时调用 `HeartbeatAsync`。心跳和激活会带上当前 `grant.json`，供服务器比较到期日。

管理员预签走 `POST /licenses/{许可Id}/offline-file`。正文是机器码和到期日，要登录并且带防伪令牌。成功时下载 JSON 文件，里面是规范授权、签名和许可码。客户端 `ImportOfflineFile` 验签、核对产品和机器码，通过后写入 `grant.json`，并把许可码记在 `state.json`，供以后心跳使用。一个产品在本机只保留一份授权，导入会替换同一产品原来的文件。

### 管理后台

页面在 `src/Licensing.Server/Components/Pages`。概览、客户、导入、审计所有已登录账号都能开。产品目录、账号、签名密钥要求超级管理员。客户详情里进入签发和单张许可。许可页可以改版本、功能、席位、到期、宽限、心跳、释放时间和换机次数，也可以暂停、恢复、吊销、强制释放和后台换机。有效的单机许可还可以生成离线授权文件。

暂停可恢复，吊销不可恢复。暂停和吊销会释放当前激活。功能代码在修改和导入时用逗号分隔。订阅到期日存成该日 `23:59:59 UTC`。

## 4. 服务器端操作步骤

### 4.1 启动

在仓库根目录：

```powershell
dotnet run --project src/Licensing.Server --launch-profile http
```

开发配置监听 `http://localhost:5277`。`https` 配置同时监听 `https://localhost:7255`。开发环境的初始账号在 `src/Licensing.Server/appsettings.Development.json`：`admin@localhost` / `Admin-Change1`。生产环境把 `Bootstrap:Email`、`Bootstrap:Password` 和 `Signing:PfxPassword` 放到环境变量或服务器自己的配置里，不要写进仓库。首次启动之后再改 Bootstrap 密码不会改已有账号。

生产环境请把 `ASPNETCORE_ENVIRONMENT` 设成 `Production`，并在前面放 HTTPS。开发配置里的密码只用于本机。

备份时停掉进程或利用 SQLite 的在线备份，把整个 `storage/` 拷走。恢复时目录里要同时有数据库、`keys` 和 `signing-password.txt`（或配置中的 PFX 口令）。只恢复数据库而没有对应的 PFX，已发出的授权将无法续签。

### 4.2 登录后的日常顺序

1. 用超级管理员打开「产品目录」。产品标识只能是 1 到 64 位的字母、数字、点、下划线和横线，例如 `demo.product`。先加产品，再加版本代码和功能代码。桌面程序启动时带的就是这个产品标识。页面上所有产品共用同一组输入框，填完要点该产品自己的「添加版本」或「添加功能」。
2. 打开「客户」，新建客户。名称必填。邮箱、公司、电话、备注可选。
3. 进入客户，选择「签发」。选产品、种类、版本和功能。永久许可勾选后不填到期日。订阅必须填到期日。单机的席位固定为 1，不显示席位数。机器池和浮动要填席位。加密锁要填锁号。老码要填原来的注册码。使用人备注只作显示。每年自助换机次数默认 0，也就是只能后台换。
4. 签发成功后页面给出 25 位许可码，形如 `ABCDE-FGHJK-LMNPQ-RSTUV-WXYZ2`。把它交给客户。服务器不保存成可以再次计算的旧算法，丢了就只能在许可详情里查看当时显示的那一串。
5. 客户激活之后，打开这张许可。激活表里有机器码、上次心跳、时钟回拨、程序版本，以及加密锁快照是否和服务器记录不一致。

界面右上角可切中文或 English。

### 4.3 导入已经发出的老注册码

「导入老码」里每行一个码。比对忽略空白和各种横线，不区分大小写，不绑机器。选好客户、产品、版本和功能后再导入。这些码不会被服务器重写成新格式。

### 4.4 暂停、吊销、释放、换机

在许可详情中：

- 「暂停」之后客户端下一次在线调用会被拒绝，并在本地留下拒绝记录。可以「恢复」。
- 「吊销」不可恢复，同样会在客户端留下拒绝记录。
- 「强制释放」立刻放开这一条激活。单机许可释放后，下一台机器可以占用，这次占用不算换机。
- 「后台换机」只用于单机和机器池。填入新机器码。单机会放开其他机器。机器池已满时会放开最久没有心跳的一台。这次不计客户的年度换机次数。
- 客户自己换机走 API `rehost`。次数用尽后返回 `RehostLimit`，只能再由后台处理。

### 4.5 给离线的单机预签

机器码不在「签发许可」那一页。签发时只生成 25 位许可码。要到这张许可的详情里填写，并且种类是「单机」、状态是「有效」，页面上才会出现「离线授权文件」。

客户在自己的程序里查看机器码。示例不联网也可以看：

```powershell
dotnet run --project src/Licensing.Sample -- machine
```

后台按下面的顺序做：

1. 打开「客户」，点进客户名称。
2. 点「签发许可」。种类选「单机」。版本、功能按这套程序来选。签完后复制许可码，交给客户备用。浮动、机器池、加密锁、导入老码没有预签，页面上不会出现机器码框。
3. 回到该客户，在许可列表里点那串许可码，进入许可详情。页头应是「单机 · 有效」。
4. 先滑过上面那张大表单，以及单独的一行「新机器码 / 后台换机」。那一行只改绑定，不下载文件。
5. 再往下是标题「离线授权文件」。说明文字是「把客户抄来的机器码填在这里」。
   - **机器码**：把客户发来的 MachineGuid 整段贴进去，不要加空格或换行。
   - **文件到期日**：默认今天起 365 天。订阅更早结束时，默认已收到订阅结束日。要盖满整个订阅，点「直到订阅结束日」。永久许可没有这个按钮，手填一个日期即可。
6. 点「生成离线授权文件」。浏览器下载 `{产品标识}-offline.json`，例如 `demo.product-offline.json`。把这个文件发给客户。

生成成功后，同一页下方的「激活」表里应出现刚才那串机器码。抄错一个字符，绑上的就是那串错码。对该行点「强制释放」，再用正确机器码重新生成。

暂停、吊销的许可整段编辑区都不会出现。先恢复成有效，再预签。

### 4.6 账号

超级管理员在「账号」里新建内部账号。密码规则与登录相同。不勾选超级管理员时，用复选框分配可见客户，然后保存。重置密码的输入框是整页共用的，要点该账号旁边的按钮。晋升为超级管理员后，对方需要退出再登录。

### 4.7 签名密钥

「签名密钥」可以轮换。新许可使用新密钥编号。旧公钥留在 `public-keys.json`。轮换后要把新的 `public-keys.json` 放进以后发出的桌面程序；已经安装的程序只要带着旧公钥，仍能验证旧授权。不要删除仍在验签期内的 PFX。

### 4.8 审计

「审计」列出登录和上述管理操作，保留 3 年。这里看不到心跳。

## 5. 客户接入方法

桌面程序引用 `Licensing.Client`。宿主自己采集机器码和加密锁快照，再交给库。库不读注册表，也不调用锁 SDK。

### 5.1 准备公钥

把服务器 `storage/public-keys.json` 随程序安装，或嵌进资源。文件形如：

```json
{
  "Keys": [
    { "Kid": "k20261105160048", "Modulus": "...", "Exponent": "AQAB" }
  ]
}
```

```csharp
var keys = PublicKeyRing.Load(publicKeyFilePath);
using var client = new LicenseClient("https://license.example.com", keys, "zh-CN");
```

构造函数可以传入已有的 `HttpClient`，以及缓存根目录 `storeRoot`。不传 `HttpClient` 时超时 20 秒。不传 `storeRoot` 时用当前用户的 LocalApplicationData，完整路径见第 1 章。语言用 `zh-CN` 或 `en`，它决定 API 的 `Accept-Language` 和本地消息。

```csharp
using var client = new LicenseClient(
    "https://license.example.com",
    keys,
    "zh-CN",
    httpClient: null,
    storeRoot: @"D:\MyApp\license");
```

### 5.2 请求内容

```csharp
var request = new LicenseCallRequest
{
    ProductId = "demo.product",
    LicenseKey = "ABCDE-FGHJK-LMNPQ-RSTUV-WXYZ2",
    MachineId = machineIdFromHost,
    AppVersion = "1.2.0",
    Dongle = null
};
```

加密锁许可把 `Dongle` 设成 `DongleSnapshot`：`DongleId`、`Edition`、`Features`。可以不填许可码，只填锁号。锁号在服务器上必须唯一，否则激活返回 `AmbiguousDongle`。

建议的宿主流程：

1. 启动时 `CheckOffline`。状态为 `Active` 就按返回的版本和功能进入程序。
2. 没有本地授权，或授权已接近 `ExpiresAt`，调用 `ActivateAsync` 或 `HeartbeatAsync`。
3. 返回 `Unreachable` 时再看一次 `CheckOffline`。缓存仍有效就继续用，到 `ExpiresAt` 为止。
4. 返回 `Suspended`、`Revoked`、`Expired` 时停止功能。不要删掉用户目录里的 `state.json` 来绕过，那会清掉已经确认的拒绝。
5. 用户换电脑时调用 `RehostAsync`，不要对同一张单机许可直接再 `ActivateAsync`。
6. 用户明确退出授权时调用 `DeactivateAsync`。
7. 离线电脑拿到管理员预签的文件后，调用 `ImportOfflineFile`。本机已有暂停、吊销或到期记录时拒绝导入。文件里的机器码必须和本机一致。

`LicenseDecision.Status` 为 `Active` 时读取 `Edition`、`Features`、`ExpiresAt`、`Kind`。`ClockRollback` 为真时只需要在界面或日志里提示，程序不必因此拒绝。`FromCache` 为真表示这次没有用到新的服务器响应。

加密锁离线时，功能列表来自本次传入的快照，不来自授权里的旧列表。授权到期时间对加密锁的离线判断不起作用。

### 5.3 用示例程序走通

服务器已启动，并且库里已有产品和许可时：

```powershell
dotnet run --project src/Licensing.Sample -- activate --server http://localhost:5277 --product demo.product --key ABCDE-FGHJK-LMNPQ-RSTUV-WXYZ2 --public-key src/Licensing.Server/storage/public-keys.json --app-version 1.0.0
```

把第一个参数换成 `heartbeat`、`check`、`deactivate`、`rehost` 或 `machine`。`machine` 只打印本机机器码，不访问服务器。导入管理员预签的文件：

```powershell
dotnet run --project src/Licensing.Sample -- import --product demo.product --file 授权文件.json --public-key src/Licensing.Server/storage/public-keys.json
```

加密锁示例：

```powershell
dotnet run --project src/Licensing.Sample -- activate --server http://localhost:5277 --product demo.product --key ABCDE-FGHJK-LMNPQ-RSTUV-WXYZ4 --dongle-id DONGLE-1 --dongle-edition pro --dongle-features export --public-key src/Licensing.Server/storage/public-keys.json
```

示例在服务器不可达或浮动席位已满时，如果本地缓存仍有效，会打印缓存并返回成功。这只是示例的取舍，正式产品应按上一节自己决定界面。

机器码必须稳定。示例读操作系统机器码。正式程序若要改用自己的标识，从第一次激活起就要用同一串，换算法会被服务器看成另一台机器。

### 5.4 接到现有的 WinForm（.NET Framework 4.8）

单机许可的授权窗口在 `src/Licensing.WinForms`。把它引用进现有的 .NET Framework 4.8 WinForm 工程，启动时调用 `LicenseForm.Ensure`，菜单里调用 `LicenseForm.Show`。公钥用服务器 `storage/public-keys.json`。机器码由窗体读取 64 位注册表里的 MachineGuid。

项目引用、公钥放置、启动代码，以及客户在尚未授权、离线导入、换机、暂停、吊销、到期等情况下的操作顺序，写在 `docs/WinForm集成与操作.md`。

同一目录下的测试程序可以用下面的命令先走通。它不是要集成进产品的主程序。

```powershell
dotnet run --project src/Licensing.WinForms
```

下面这一段是不使用授权窗体、直接调用客户端库时的做法。`Licensing.Client` 的目标框架是 `netstandard2.0`，.NET Framework 4.8 可以直接引用。库自己不读注册表，机器码由桌面程序读出来再传进去。

在 WinForm 工程里引用 `src/Licensing.Client/Licensing.Client.csproj`。老式 `packages.config` 工程则先编译出 `Licensing.Client.dll`，再安装 NuGet 包 `System.Text.Json` 8.0.5，并把该 DLL 加为引用。公钥文件用服务器上的 `storage/public-keys.json`，随安装包一起发，或嵌进资源。换签名密钥之后，要换这份公钥文件再发新版本；旧程序里已有的旧公钥仍能验旧文件。

很多 WinForm 是 32 位进程。32 位下直接打开 `Registry.LocalMachine` 会进 `Wow6432Node`，那里没有 `MachineGuid`。要显式打开 64 位视图：

```csharp
using Microsoft.Win32;

static string ReadMachineId()
{
    using (var hive = RegistryKey.OpenBaseKey(RegistryHive.LocalMachine, RegistryView.Registry64))
    using (var key = hive.OpenSubKey(@"SOFTWARE\Microsoft\Cryptography"))
    {
        var value = key == null ? null : key.GetValue("MachineGuid") as string;
        if (string.IsNullOrWhiteSpace(value))
            throw new InvalidOperationException("读不到 MachineGuid。");
        return value.Trim();
    }
}
```

在关于或授权窗口里把这串原样显示出来，让客户复制给管理员。管理员填进后台的必须是同一串。

启动时先离线检查。没有本地授权时，让用户选管理员发来的 JSON，再导入。`ProductId` 必须和后台产品标识逐字相同。

```csharp
using System.IO;
using System.Windows.Forms;
using Licensing.Client;

const string ProductId = "demo.product"; // 换成产品标识

LicenseClient CreateClient()
{
    var keys = PublicKeyRing.Load(Path.Combine(Application.StartupPath, "public-keys.json"));
    return new LicenseClient("http://localhost:5277", keys, "zh-CN");
}

LicenseCallRequest CreateRequest()
{
    return new LicenseCallRequest
    {
        ProductId = ProductId,
        MachineId = ReadMachineId(),
        AppVersion = Application.ProductVersion
    };
}

void OnStartup()
{
    using (var client = CreateClient())
    {
        var decision = client.CheckOffline(CreateRequest());
        if (decision.Status == LicenseStatuses.Active)
        {
            EnterMain(decision); // 用 decision.Edition、decision.Features
            return;
        }
        ShowLicenseForm(decision.Message); // 显示机器码，并提供「导入授权文件」
    }
}

void ImportGrantFile(string path)
{
    using (var client = CreateClient())
    {
        var json = File.ReadAllText(path);
        var decision = client.ImportOfflineFile(CreateRequest(), json);
        if (decision.Status != LicenseStatuses.Active)
        {
            MessageBox.Show(decision.Message ?? decision.Status);
            return;
        }
        EnterMain(decision);
    }
}
```

导入成功后，库把验过的授权写到 `%LOCALAPPDATA%\Licensing\{产品标识}\grant.json`，许可码写在同目录的 `state.json`。要改存放位置时，给 `LicenseClient` 传入同一个 `storeRoot`，见第 1 章。以后这台电脑启动只调用 `CheckOffline`，不必再选文件。文件里的机器码和本机读到的不一致时，返回 `MachineMismatch`，不写 `grant.json`。本机若已有暂停、吊销或到期记录，导入会被拒绝，直到一次成功的在线调用把记录清掉。

以后这台电脑能上网时，用同一个请求调用 `HeartbeatAsync`。许可码可以留空，库会用 `state.json` 里记住的那一串。返回 `Unreachable` 时再 `CheckOffline`，未过文件到期日就继续用。返回 `Suspended`、`Revoked`、`Expired` 时停用功能，保留 `state.json`。

## 6. 疑难示例

下面的状态字符串就是 `LicenseDecision.Status` 和 API 正文里的 `status`。

**签发时没有填机器码，是不是没绑定？**

联网激活时，绑定发生在第一次成功激活。签发完成时这张码还没有机器。谁先激活成功，单机许可就归谁。管理员预签时，绑定发生在生成文件的那一刻。激活表里能看到机器码。

**离线电脑怎样第一次激活？**

客户用 `machine` 或程序里的显示功能抄出机器码。管理员在单机许可上生成离线授权文件，默认 365 天。订阅要覆盖到许可结束时，点「直到订阅结束日」。客户执行 `import`。文件到期前这台电脑可以不联网。到期后要再签一份，或者改为联网激活。

**预签文件能填到订阅结束日之后，或者填 36500 天吗？**

订阅许可填得更晚，签出来的文件仍停在订阅结束日当天。36500 天只在永久许可上会变成大约一百年。这台电脑若一直不上网，暂停和吊销在文件到期前到不了它。

**给新电脑预签之后，旧电脑还能用吗？**

能，直到旧文件自己的到期日。服务器撤不回已经拷走的文件。这次换机不计客户每年的自助次数。

**已经暂停的电脑又导入了旧文件。**

本地还留着拒绝记录时，导入会被拒绝。下一次成功的在线激活会清掉记录。删掉 `state.json` 之后，旧文件又能导入。

**第二台电脑提示 MachineInUse。**

单机许可已经有一台机器占着。客户应在新电脑上走换机，或由管理员在许可详情里后台换机、或先强制释放。同一台电脑注销后再激活不算换机。本年次数用尽时状态是 `RehostLimit`。

**换机按钮对浮动许可不可用。**

浮动和加密锁、老码不走换机接口。浮动席位在注销时立即释放；没有注销时，超过「席位释放小时」没有心跳才会释放。宽限期内旧机器仍可能靠本地授权运行，这是浮动许可接受的超卖。

**想把 grant.json 换到别的目录。**

可以换根目录，不能改文件名。构造 `LicenseClient` 时传入 `storeRoot`。文件仍叫 `grant.json` 和 `state.json`，仍放在 `{storeRoot}\Licensing\{产品标识}\` 下。程序里每一处创建客户端都要传同一个根，否则导入写在一处、启动时又到默认的 `%LOCALAPPDATA%` 去找。

**断网后立刻不能用。**

先看 `grant.json` 是否存在，以及其中的 `exp`。单机、机器池和老码过了 `exp` 就返回 `Expired`。没有预签文件、也没有成功联网激活过的电脑，本来就没有本地授权。加密锁没有快照时返回 `DongleMissing`；有快照且没有拒绝记录时，即使没有 `grant.json` 也可以离线使用。

**服务器已经吊销，客户端还能用。**

这台机器还没有一次成功的在线调用。吊销写不进它的磁盘。连上之后状态变为 `Revoked`，并写入 `state.json`。此后删掉 `grant.json` 也不够，还要看 `state.json` 里的拒绝记录。

**暂停已经恢复，客户端仍显示暂停。**

拒绝记录要等下一次成功的 `Active` 才会清掉。让客户再执行一次激活或心跳。

**老码多写了横线或大小写不同，却找不到。**

比对会去掉空白和 `-`、`‐`、`‑`、`–`、`—`，并转成大写。其他符号会留下来。导入的原文和客户输入在去掉这些字符后必须一致。

**加密锁功能跟后台不一样。**

离线功能以宿主快照为准。后台只在激活记录上标记「不一致」，不改客户端本次可用的功能。锁号和许可上的锁号不同才返回 `DongleMismatch`。

**提示时钟回拨。**

本机时间比上次记录早了 5 分钟以上。授权仍然有效。把时间改回正确后，下一次心跳会把警告送到服务器，许可详情的「时钟回拨」列能看到时间。

**提示 InvalidSignature 或 ServerError。**

`InvalidSignature` 表示公钥对不上，或授权字节被改过。确认程序带的 `public-keys.json` 来自这台服务器，并且轮换后的新公钥已经放进新版本。`ServerError` 表示服务器返回了非约定正文或发生了未处理异常，看服务端日志，不要把它当成许可无效。

**提示 Unreachable，但程序仍能进入。**

库没有删缓存。若缓存未过期，离线检查仍然是 `Active`。示例程序在这种情况下会打印缓存并以成功结束。

**后台能登录，桌面程序说没有这张许可。**

产品标识必须和目录里的 `PublicId` 一致，许可码必须属于这个产品。码属于别的产品时同样是 `NotFound`。

**普通账号看不见某个客户。**

超级管理员还没有把该客户分配给这个账号。分配或晋升之后要重新登录。

**换了服务器机器或只拷了数据库，签名失败。**

PFX 和口令不在数据库里。`storage/keys` 与 `signing-password.txt`（或 `Signing:PfxPassword`）要和数据库一起走。

**想迁到 PostgreSQL。**

不能只改连接字符串。需要加上 PostgreSQL 提供程序、为该提供程序生成迁移，再把现有数据拷过去。SQLite 上按时间排序是在内存里做的，换库之后可以改回数据库排序。
